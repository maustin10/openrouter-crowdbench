Why CrowdBench does not store your key
  • Browser memory only: after validation, the field is cleared and the key exists only in this open page's JavaScript memory. It is never placed in cookies, local storage, session storage, or a URL.
  • Request-scoped transmission: the key is sent only in a dedicated request header to the CrowdBench API for catalog, quota, and tests—over encrypted HTTPS when hosted, or directly to your own loopback server when local. It is never included in request JSON or query strings.
  • Ephemeral execution: during a test, the backend passes the key directly to one in-memory worker thread. The job record itself has no key field, and the reference is released when the run finishes.
  • Sanitized public history: saved reports contain model IDs, timestamps, status codes, latency, format checks, and short probe evidence—never credentials. Server access logs record the URL and status, not request headers.
  • You stay in control: disconnecting or closing the page removes the browser copy. For a public deployment, CrowdBench must run over HTTPS; use a limited, revocable OpenRouter key for additional protection.
